
# MediLink — Development Plan

Team: 
- Mehjabin Rahman Mowrin: Engineering Manager / Developer
- Rim Belbbas: Appointments Developer
- Yessir Khelifi: Notifications Developer

Cycle Duration: Five working days

Cycle Goal: Improve the reliability of appointment management and notification workflows while demonstrating effective engineering-management practices.

Day 1: Planning
- Set up the repository and project board.
- Assign work items and priorities.
- Review acceptance criteria.
- Confirm the WIP limit and Definition of Done.

Day 2: Development
- Start approved work items.
- Track dependencies and blockers.
- Conduct asynchronous daily updates.

Day 3:  Development and Review
- Continue assigned work.
- Submit reviewable artifacts or pull requests.
- Request peer reviews.
- Report workflow problems.

Day 4: Verification
- Conduct reviews and verification.
- Resolve blockers where possible.
- Gather workflow evidence.

Day 5: Evaluation
- Review completed and unfinished issues.
- Record workflow observations.
- Discuss process improvements.
- Prepare assignment evidence.

 Working Agreements: 
- WIP limit: 2 items in In Progress.
- Every issue requires an owner and acceptance criteria.
- Every completed item requires verification.
- Daily updates are asynchronous.
- Urgent blockers and production incidents may
  require synchronous discussions.
